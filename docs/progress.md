# Интеллектуальный поиск v0.3 — 15.10.2026

Реранкер реализован, установлен и включён в стандартный запуск на этой машине.
SQLite сохранён. Доступен отдельный поиск без LLM и ответы GigaChat с тем же
поисковым pipeline. Промышленная банковская приёмка не объявляется выполненной.

## Дополнения v0.3

- RerankerProvider и локальный cross-encoder mmarco-mMiniLMv2-L12-H384-v1,
  закреплённая ревизия/контрольные суммы, safetensors, CPU, offline inference.
- Исправлена глобальная RRF-сортировка: прежнее чередование документов больше
  не определяет релевантность. Пул кандидатов сохраняет независимые пути поиска.
- Окна длинного текста, лучшие spans, ограничение кандидатов/окон; явные
  диагностика усечений и fallback при сбое, отсутствие скрытого отключения.
- Новый `/projects/{project}/search`, фильтр документов и top_k, локальный
  экран «Интеллектуальный поиск», оценки и оригинальные страницы, журнал поиска.
- Повторная проверка ACL и версии корпуса после локального inference;
  результаты UI сбрасываются при изменении источников или состава проекта.
- Полный unittest: 109 тестов прошли (включая 14 новых search и новый UI-сценарий).
- Реальные e5/cross-encoder: 30 синтетических документов, 40 размеченных вопросов;
  Recall@5=1.0, MRR@10=1.0, nDCG@10=1.0. Независимые обязательные альтернативы
  сохранены. P95=0.119 с на этой машине/коротких документах.
- Реальный GigaChat: OAuth/TLS, загрузка трёх документов во временную SQLite,
  search API с реранкером, два асинхронных ответа (10/15 млн и определение),
  предупреждение о расхождении, отдельная валидация и аудит пяти LLM-попыток.

Рабочий сервер перезапущен и проверен через HTTP: UI 8502 → 200,
health → hybrid, reranker.enabled=true, worker_running=true, worker_errors=0.
Запрос к существующему синтетическому демопроекту → reranker.status=applied,
10 кандидатов/окон, 35 мс. GigaChat настроен; разрешения реальных документов
не изменялись.

Воспроизведение и ограничения: `docs/evaluation.md`, `README.md`.

## Протокол предыдущего этапа v0.2

# SQLite MVP — состояние 15.10.2026

**Согласованный локальный MVP реализован и проверен.** Пользователь оставил
SQLite и сузил текущую задачу до технически корректного сценария загрузки
документов и вопросов по ним. Корпоративное развёртывание из первоначального
ТЗ не объявляется выполненным.

## Готовый пользовательский путь

1. `.venv/bin/python manage.py bank` → http://127.0.0.1:8502.
2. Подключение GigaChat в боковой панели, проверка модели и явное разрешение
   внешних вопросов/фрагментов. Настройка сохраняется, ключ остаётся на сервере.
3. Создание проекта, загрузка PDF/сканов/TXT с отдельной политикой передачи.
4. Фоновый parsing/OCR/индексация, автоматически обновляемые статусы.
5. Вопрос → сохраняемое задание → содержательный ответ GigaChat → точные цитаты,
   ссылки на оригинальные страницы, расхождения и ограничения охвата.
6. Уточняющий вопрос в диалоге, новая тема, история, ревью и экспорт.

## Выполненные технические пункты

| Потребность | Реализация |
|---|---|
| Архитектура на SQLite | Отдельные storage/ingest/retrieval/generation/jobs/API/UI модули, WAL, аддитивная схема v3, резервная копия |
| Устойчивый ingest | Persistent jobs, отдельный parser subprocess, общий timeout и лимиты, страницы с ошибками не теряются |
| Восстановление | Ограниченное восстановление running jobs; повторная обработка создаёт новую версию |
| Смысловой поиск | Локальные e5 vectors + FTS5; индексы старых документов перестраиваются по каноническим блокам |
| Содержательные ответы | Claims/assessments по JSON Schema, проверка ID/цитат/чисел, отдельный entailment-вызов |
| Большой контекст | Ограниченный batch-план, разбиение после 422, ID сохраняются, неполный анализ маркируется |
| Асинхронные вопросы | HTTP 202, persistent question_jobs, idempotency key, UI polling, до 5 pending на пользователя/проект |
| Диалог | Последние вопросы используются для ссылочных уточнений; новая тема не наследует предмет старого вопроса |
| Применимость | Дата as_of, семантическое сравнение, серверные денежные расхождения; будущая/недоказанная поправка не получает приоритет |
| ACL и отправка | Project/document ACL до каждого поиска/внешнего вызова/просмотра; per-document policy; история повторно проверяется |
| Аудит LLM | Начатые/успешные/отклонённые/ошибочные попытки с model/usage/IDs без сохранения сырого prompt |
| OCR correction | Отдельная исправленная редакция страницы, старый текст и оригинальные байты неизменны |
| Контракты/выгрузки | /api/v1/openapi.json, JSON и HTML-отчёт для печати в PDF, ревью аудитора |

ResourceWarning тестового multipart buffer; итоговый набор проходит.

## Не включено в локальный MVP

- SSO/OIDC, многопользовательское внешнее развёртывание, AV sandbox и шифрование
  хранения, корпоративный audit sink. Локальный API слушает только loopback.
- Полный layout-aware OCR, координатная подсветка, все таблицы/сноски и
  междокументные ссылки, ручная подтверждаемая онтология всех видов норм.
- Claims-index, DOCX и прямой PDF-рендерер (есть печатный HTML),
  нагрузочная приёмка 5000 страниц и утверждённые банковские метрики на 200 вопросах.

Это не препятствует согласованному локальному сценарию документов/вопросов.
При работе с реальными банковскими данными нужна отдельная ИБ-приёмка;
правильность смысла и применимости не гарантируется самим фактом наличия цитат.
Coverage остаётся честно partial при известных ограничениях.
