# Fast RAG v5: выбранная модель и больше документов

Дата проверки: 2026-10-16.

## Поведение

Лимит вычисляется заново для модели конкретного вопроса. Выбор модели в чате
не меняет настройки другого параллельного вопроса. API `/provider/models`
возвращает бюджеты вместе с доступными моделями; подсказка у выбора модели
показывает действующий бюджет. Модель не заменяется автоматически.

| Параметр | До изменения | Сейчас |
|---|---:|---:|
| Фрагменты для генерации | 8 | 64 по умолчанию, настройкой до 128 |
| Текст источников | 10 000 символов | До 240 000 для окна 128 000 токенов |
| Обычный фрагмент | 2 400 символов | 6 000 символов |
| Окно GigaChat-2 / 2-Pro / 2-Max | Общий лимит 32 768 | 128 000 токенов |
| Резерв выхода | 2 500 токенов | 6 000 для большого окна, иначе 2 500 |
| Генерация | Один completion | Один completion |
| Подсчёт входа | UTF-8-байты | Один пакетный `/tokens/count` выбранной модели |

Число фрагментов не равно числу загруженных документов. В одной библиотеке
может быть больше файлов: поиск проходит по доступным документам, затем
отбираются релевантные места в пределах бюджета. Представление каждого файла
в одном ответе не гарантируется. При исключении документов найденной выдачи
из контекста ответ получает пояснение об ограничении охвата.

Загрузка уже поддерживает несколько файлов. HTTP API принимает до 100 файлов
в одном пакете общим объёмом до 100 MiB, каждый файл — до 25 MiB; интерфейс
отправляет выбранные файлы отдельно. Эти ограничения размера файлов сохранены.

## Лимиты моделей

Окно 128 000 проверено по официальным страницам
[GigaChat 2 Lite](https://developers.sber.ru/docs/ru/gigachat/models/gigachat-2-lite),
[Pro](https://developers.sber.ru/docs/ru/gigachat/models/gigachat-2-pro),
[Max](https://developers.sber.ru/docs/ru/gigachat/models/gigachat-2-max).
Идентификаторы семейства с версией после двоеточия используют тот же профиль.

Для неизвестного ID используется прежний консервативный бюджет 32 768 с явной
отметкой `conservative_fallback`; это не заявление о фактическом окне модели.
Если для новой/корпоративной модели известен иной подтверждённый предел, его
можно задать через `GIGACHAT_MODEL_CONTEXT_LIMITS`, например:

```bash
export GIGACHAT_MODEL_CONTEXT_LIMITS='{"GigaChat-custom":16384}'
```

Серверная настройка `GIGACHAT_CONTEXT_TOKENS` может дополнительно уменьшить
бюджет. Она не увеличивает документированный предел известной модели.
По умолчанию переменная пустая, чтобы не сохранять старый общий барьер 32 768.

## Сборка контекста

1. Поиск для Fast получает увеличенные лимиты кандидатов и текста, вычисленные
   для выбранной модели. Реранкер остаётся локальным; его лимит 384 токена на
   пару не меняется, длинные фрагменты оцениваются окнами.
2. Точные коды мер сохраняют приоритет. Лучший фрагмент каждой найденной версии
   документа отбирается до дополнительных фрагментов уже представленного файла.
3. Отобранные снимки текста и служебная часть считаются одним пакетным запросом
   `/tokens/count`. Строки считаются выбранной моделью. К сумме добавляется запас
   на обрамление и границы компонентов: 1 024 токена, 32 на источник и 2%.
   Это оценка assembled prompt с резервом, не точный счёт всех внутренних токенов API.
4. В общий лимит заранее включается резерв ответа. Не помещающийся источник
   пропускается целиком, после чего проверяются следующие. ID цитат перенумеровываются.
   Строки точных мер не обрезаются для заполнения остатка бюджета.
5. Если счётчик недоступен или вернул невалидные данные, действует оценка по
   UTF-8-байтам окончательного JSON. Это может уменьшить охват, но не отключает
   проверку размера. Авторизационные 401/403 завершают запрос явно.
6. Подсчёт не повторяется автоматически; для обращения к `/tokens/count` задан
   таймаут до 15 секунд. OAuth при необходимости выполняется отдельно. Повторная
   проверка ACL и версии корпуса проводится перед передачей и перед генерацией.

В журнале и манифесте ответа записываются выбранная модель, бюджет, метод подсчёта,
оценка входа, представленные документы и исключённые фрагменты. Исходные тексты
и ключи не записываются в технические журналы вызовов.

Больший контекст может увеличить время и стоимость ответа. Он улучшает охват
найденных данных, но не исправляет OCR и не доказывает корректность общих выводов.

## Проверки

- 156 локальных тестов, включая 10 новых: переключение модели и параллельные
  вопросы, административные ограничения, 50 документов, пересчёт ID цитат,
  отказ/невалидные ответы счётчика, резерв выхода и повторную проверку доступа.
- `scripts/evaluate_many_documents.py --live` создаёт временную SQLite и загружает
  через API 50 синтетических файлов. Используются реальные E5, cross-encoder и
  GigaChat-2. Пользовательская база не читается и не изменяется.
- В отчёте `evaluation/results/many-documents-live.json`: 50/50 документов
  представлены в контексте; один подсчёт и один completion; 26 013 входных токенов,
  746 выходных; ответ содержит специальные требования первого и пятидесятого файлов.
  Поиск и ответ заняли 24,43 секунды в этом прогоне (без времени загрузки/индексации).
- Это синтетическая проверка вместимости и корректности пути данных; она не
  измеряет качество ответов на произвольные 50 реальных нормативных документов.

Настройки перечислены в `.env.example`; файл не загружается автоматически.
Для обычного запуска достаточно перезапустить `manage.py bank` с прежним путём
к базе. Переиндексация и повторная загрузка пользовательских документов не нужны.
