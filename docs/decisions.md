# Решения и отклонения от ТЗ v1.2

1. **Адаптация текущего стека.** Сохранены Flask/Streamlit/pypdf вместо немедленного
переписывания в FastAPI/Next.js/PyMuPDF. Мастер-промпт разрешает адаптировать
подходящий код. Новый контур изолирован в bank, legacy данные не мигрируются молча.
2. **Локальный этап вместо имитации инфраструктуры.** SQLite и отдельный поток
с сохранённой очередью дают проверяемую цепочку на данном компьютере. PostgreSQL,
Redis, MinIO, Docker Compose полного стека остаются незавершёнными требованиями M1.
3. **Готовность честно ограничена.** Нельзя считать M1–M5 выполненными полностью.
Нет экспертного набора 200 вопросов, SSO, приёмки банка и production deployment.
4. **Дата не определяет приоритет.** Новый документ/метаданные не являются
доказательством отмены. ContradictionService даёт предварительные расхождения;
amendment/date reasoning и нормализация сроков ещё не закончены.
5. **Охват всегда ограниченный.** Пока нет полного разрешения cross-references
и проверки применимости, complete не выдаётся даже при успешном обходе всех индексов.
6. **Ключ и scope.** Пользователь подтвердил GIGACHAT_API_PERS. Предоставленный
ключ записан только в игнорируемый secrets/gigachat-bank.key (0600). Ранее
настроенный ключ не перезаписывался. PERS подходит для проверки синтетики,
но не удовлетворяет корпоративному требованию GC-02. Модель GigaChat-3-Pro
взята из существующей конфигурации и доступ проверен через /models.
Автоматической смены модели нет.
7. **Документация API сверена.** Официальные страницы просмотрены 15.10.2026:
[OAuth](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-token),
[chat v1](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-chat),
[JSON Schema](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output).
Некоторые примеры официальной документации отключают TLS — это не перенесено в код,
поскольку противоречит SEC/GC требованиям. Везде проверка TLS включена.
8. **Ограниченная генерация.** Новый GigaChat-путь возвращает отобранные точные
цитаты, не произвольный юридический пересказ. Это промежуточная функциональность,
а не выполнение всех FR-18–FR-23. При ошибке валидации результат отклоняется.
9. **Экспорт.** Пока только JSON с полным манифестом. DOCX/PDF отчёт остаётся
требованием. Нет фиктивной кнопки «PDF» с текстовым файлом внутри.
10. **Claims.** Feature flag в примере конфигурации зарезервирован; extractor
отсутствует. Изменение ENABLE_CLAIMS_INDEX не включает несуществующую реализацию.


## Обновление после уточнения пользователя (SQLite MVP)

11. Пользователь прямо разрешил оставить SQLite и попросил работающий сценарий
загрузки/вопросов. PostgreSQL, Redis, S3 и SSO не блокируют локальный MVP;
они не объявляются выполненными. Архитектура остаётся модульной с границами провайдеров.
12. Решение 8 об extractive-only режиме заменено: реализован содержательный ответ
claims/assessments, источник/числовой валидатор и отдельный entailment. Это всё ещё
не обещание банковской экспертной точности. Пустые или неподтверждённые ответы
не принимаются как успешные факты.
13. Questions теперь асинхронны по умолчанию, с SQLite queue, conversation IDs,
idempotency keys, recovery и UI polling. Есть sync-совместимость для локальных
интеграций. Фоновые очереди работают в одном процессе с эксклюзивным lock.
14. Разрешение GigaChat настраивается явно в UI и сохраняется сервером. Ключ
автоматически не переносится в браузер; используются уже заданные scope/model/CA.
Пользователь может разрешить передачу при загрузке конкретных документов.
15. Реальные интеграционные испытания ограничены синтетическими fixtures во
временной базе. Корпоративные документы и политики рабочей базы не затрагивались.
16. Добавлены безопасный HTML-отчёт для печати в PDF и JSON. Прямой DOCX/PDF renderer
остаётся отдельной функцией; HTML-файл не выдаётся за PDF.


## Интеллектуальный поиск v0.3

17. Реранкинг обязателен в штатном запуске. Выбран локальный multilingual
cross-encoder/mmarco-mMiniLMv2-L12-H384-v1@1427fd652930e4ba29e8149678df786c240d8825:
поддерживает русский, Apache-2.0, подходит для CPU. Загружены только safetensors
и tokenizer/config; trust_remote_code=False, checksum manifest, явный installer.
18. Ошибка ранжирования сохраняет доступную RRF-выдачу с failed, а не скрытым
applied; отсутствие весов при старте требует исправить установку. Отключение
возможно только явным BANK_RERANKER_MODE=disabled и видно пользователю.
19. Глобальный RRF заменяет прежний порядок чередования документов. Отдельные
пути альтернатив/исключений остаются; cross-encoder не принимает решения о
юридической применимости и не отменяет предупреждения о расхождениях.
20. Standalone search не требует GigaChat/external_allowed. Применяет те же
ACL, corpus snapshot и повторные проверки доступа, что путь ответа.
21. Набор 30 документов/40 вопросов с идеальным итоговым retrieval score —
синтетическая регрессия. Не называть его банковским benchmark или доказательством
выполнения экспертных приёмочных целей первоначального ТЗ.
