# Исправления после аудита, 15.10.2026

Исходный аудит сохранён как протокол обнаруженных дефектов. Этот документ
описывает последующие изменения; он не заменяет банковскую экспертную приёмку.
SQLite оставлен по указанию пользователя. SSO отложен пользователем отдельно.
Полная [матрица всех 98 требований и сценариев](requirements-status.md) сохраняет
также пункты, для которых пока нет нового подтверждения.

## Исправленные дефекты

| Дефект | Реализация и проверка |
|---|---|
| A1, A2 | `norms.py`: деньги, сроки, вид дней, проценты, операторы, продукты, типы лимитов, периоды. Противоположные операторы при одинаковой сумме больше не пропускаются. При отказе LLM обе цитаты и предупреждение сохраняются |
| A3 | `as_of` проходит в retrieval; проверяются сохранённые версии. Датированная поправка связывается с предметом/пунктом и значениями; сервер показывает значение для даты проверки. Новизна файла не считается юридическим приоритетом |
| A4, A5 | JSON Schema Draft 2020-12 на сервере, проверка операторов/единиц/дат, запрет постороннего основания поправки. Отдельный entailment остаётся обязательным для утверждений модели |
| A6 | Типизированный реестр, предложения метаданных, подтверждение и журнал изменений, связи с пунктом-основанием, фильтры API/UI |
| A7 | Прямой PDF с кириллицей, источниками, датой, ограничениями и заключениями аудиторов. Неподдерживаемый формат возвращает 400. PDF отрендерен и просмотрен |
| A8 | Poppler bbox-layout, OCR TSV с фактической confidence, координаты областей текста, просмотр PDF/TIFF с подсветкой, локальные и зарегистрированные междокументные ссылки, определения и продолжения пунктов. Сложные таблицы и неизвестные связи остаются ограничением |
| A9 | Подсчёт токенов провайдером перед генерацией, резерв ответа/схемы, консервативный fallback, ограниченные межгрупповые сравнения с исходными block_id, бюджет вопроса/вызовов/времени. Непроверенные группы отмечаются явно |
| A10 | API/UI ролей и ACL, ClamAV INSTREAM с отказом при ошибке настроенного сканера, retention с предварительным списком, AES-256-GCM backup/restore с проверкой целостности, журнал чтения/экспорта, панель токенов и стоимости по настроенному тарифу. SSO отложен |

Дополнительно: включаемый индекс типизированных числовых утверждений; основной
поиск всегда использует полный canonical text. FTS/точные индексы/связи/claims
перестраиваются из canonical без повторного OCR, в том числе без embeddings.
Добавлен статус аудиторского заключения `needs_documents`.

## Проверки

- Полный локальный набор: **126 тестов пройдено** (109 исходных и 17 новых регрессий).
- GitHub CI первого коммита прошёл на чистом Ubuntu/Python 3.12.
- Десять исходных диагностических проб: **10/10**.
- Новые тесты проверяют PDF, фильтры/claims/reindex, связи, ACL экспортов,
  антивирусные отказы, зашифрованное восстановление и подмену ciphertext,
  координаты, TIFF frame, проценты, календарные годы и retention.
- Финальный live-прогон: **5/5 автоматических сценариев пройдено**,
  `evaluation/results/compliance-verified-live.json`, GigaChat-3-Pro:32.4.30.3.
  Проверены поправка до/после даты, разные продукты, рабочие дни и противоположные
  операторы. Итоговые тексты также просмотрены: для марта указан лимит 10 млн,
  для августа — 15 млн; неразрешённые сроки/операторы сохраняют обе нормы.
  В историческом сценарии часть модельных утверждений исключена entailment-проверкой;
  предупреждение сохранено. Все данные синтетические, экспертная приёмка не заменена.
  Предыдущие неуспешные прогоны сохранены рядом, а не переписаны удачным результатом.
- Поиск с реальными e5/cross-encoder проверяется отдельно скриптом
  `scripts/evaluate_bank_search.py`; краткий корпус не доказывает полноту большого.
- **5000 страниц, включая 500 реальных OCR, 50 PDF: пройдено.** 150.9 с на этой
  машине, все страницы сохранены, 0 ошибок извлечения, SQLite 43.5 MB; lexical
  search 0.509 с. `evaluation/results/capacity-5000.json`. Это синтетическая
  простая верстка, без embeddings/reranking в нагрузочном прогоне и без внешнего API.
- После неудачной коррекции JSON/цитат независимо корректные утверждения могут
  пройти отдельную entailment-проверку и сохраниться с явной отметкой partial.
  Невалидные утверждения не становятся допустимыми из-за этого fallback.
- Модель выбирает `quote_id` из закрытого списка источников; сервер подставляет
  неизменный canonical text и затем проверяет схему, числа и смысл. Это устраняет
  ошибки перепечатывания цитат, не ослабляя проверку происхождения. Неизвестные ID
  и пустые evidence отклоняются. Цифры в точном имени цитируемого файла после
  «В документе ...» не принимаются за числа нормы; выдуманные имена/суммы отвергаются.
- При включении claims-index существующие версии автоматически переиндексируются
  из canonical, с новой версией индекса и записью в аудит. Повторный OCR не нужен.

## Оставшиеся условия и ограничения

1. **Банковская приёмка:** нужны разрешённые 200 вопросов с экспертной разметкой,
   целевые документы, корпоративный GigaChat и решение ИБ. Синтетические примеры
   не заменяют их и не доказывают требуемые groundedness/precision/recall.
2. **Сложная верстка:** координаты теперь реальны, но восстановление объединённых
   ячеек, печатной пагинации и произвольных сносок не является полным. Нужны
   размеченные образцы и специализированный layout/OCR provider для таких форм.
3. **Смысл норм:** детерминированный модуль поддерживает явные числовые нормы;
   произвольные обязанности и множественные взаимосвязанные условия проверяет
   LLM и аудитор. Сервер никогда не утверждает, что весь корпус непротиворечив.
4. **Хранилище:** основной SQLite и его FTS не зашифрованы приложением. Нужен
   зашифрованный том в целевом контуре; шифрование backup не шифрует рабочую БД.
   Физическое удаление WAL/свободных страниц и копий требует политики диска/backup.
5. **Интеграции:** ClamAV реализован, но адрес сканера не предоставлен. По умолчанию
   локальный режим явно сообщает `not_configured`; `BANK_REQUIRE_AV=true` закрывает
   загрузку без сканера. Централизованное хранилище секретов должно предоставлять
   защищённый файл или окружение серверному процессу.
6. **Версии модели:** `GIGACHAT_ALLOWED_MODEL_VERSIONS` включает запрет публикации
   ответов новой непроверенной версии. Без списка версий действует мониторинг,
   а не автоматическое одобрение модели. Тариф задаётся оператором, не угадывается.
7. **Масштаб и SLA:** ёмкость ingest на синтетических 5000/500 проверена;
   end-to-end SLA с embeddings, reranker и GigaChat на банковских документах
   и целевой инфраструктуре ещё не принят. Качество OCR CER/WER не измерялось.

Эти пункты остаются открытыми явно. Репозиторий — работающий локальный вариант
с проверенными исправлениями, а не сертификат полного соответствия банковскому ТЗ.
