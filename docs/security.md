# Безопасность SQLite MVP

Приложение работает локально на loopback. Local token — серверная аутентификация,
не корпоративный SSO. Запуск без LOCAL_DEMO_MODE либо с APP_ENV=production
блокируется. Пользователь согласовал этот локальный объём; промышленная ИБ-приёмка
и обработка банковской тайны требуют отдельного этапа.

Проектные роли и document ACL проверяются в Store до retrieval/публикации индекса,
просмотра оригинала/страницы, истории и экспорта. Чужие документы не раскрываются
в именах, цитатах, статистике или coverage. При отзыве доступа к историческому
корпусу весь snapshot скрывается, но не уничтожается. Диалог принадлежит конкретному
пользователю/проекту; перенести его ID в другой scope нельзя.

Ключ GigaChat находится в ignored secrets/gigachat-bank.key (0600) или env,
никогда в браузере. TLS включён, перенаправления с credential не разрешаются.
Глобальная external policy выключена по умолчанию; локальный пользователь настройки
может включить её в UI. На каждом документе отдельная external_allowed.
Проверки выполняются перед каждым внешним запросом: генерация, retry, verifier.
Отправляются только вопрос, ограниченная история вопросов и найденные фрагменты.
Содержимое файлов не выполняется, у модели нет инструментов и доступа к системе.

Ответ проверяется по JSON-схеме, существующим IDs, точным подстрокам и числам;
отдельный LLM-вызов проверяет смысловую поддержку. Пропущенные/отклонённые judgments
не считаются подтверждёнными. Серверный конфликт нельзя убрать инструкцией из
PDF. Возможность ошибки LLM сохраняется; результат не заменяет суждение аудитора.

Persisted llm_calls содержит stage, модель, usage, IDs, hash шаблона и статус
каждой попытки, включая ошибки. Сырые prompts/документы не пишутся в обычные логи.
Ответы и audit_events защищены SQLite-триггерами от UPDATE, audit — от DELETE.
Это не защита от администратора файла; промышленный append-only sink не реализован.
В отчёте HTML все значения модели/документа экранируются; скрипты из источника
не становятся кодом HTML.

Размер файла до 25 MiB, пакета до 100 MiB, максимум 100 файлов за запрос,
PDF до 5000 страниц, TIFF до 500 кадров. Parser вынесен в отдельный процесс,
имеет wall/CPU/file-size/FD ограничения и на Linux memory limit; на таймауте
завершается группа процессов. Это защита устойчивости, не AV и не контейнерная
песочница. OCR errors учитываются постранично. Имена файлов не используются
как пути оригиналов. Исправления OCR создают новые редакции с журналом.

Очередь вопросов ограничена пятью pending на пользователя/проект; модельные
вызовы ограничены числом попыток и общим бюджетом, есть circuit breaker.
Идемпотентные ключи и восстановление очереди снижают повторные списания.
Сбой процесса в момент внешнего запроса до сохранения результата всё ещё может
привести к повторному вызову после рестарта: exactly-once внешнего API не обещается.

Не включены: OIDC/SAML, шифрование SQLite/backup, AV/parser sandbox с network isolation,
административный интерфейс выдачи ролей, внешний audit sink, централизованный
secret manager и банковские retention policies. Backup также содержит документы
и историю, его следует хранить в том же контролируемом локальном контуре.


## Локальный реранкер

Вопросы и блоки оцениваются на CPU без сети. Модель устанавливается отдельной
явной командой по закреплённой ревизии Hugging Face; веса safetensors сверяются
с upstream SHA-256, затем все файлы проверяются при старте по manifest.
trust_remote_code отключён, local_files_only включён. Права фильтруются до
оценки; после неё проверяются снова вместе с версией корпуса. Runtime-сбой
не раскрывает текст исключения модели; в манифесте только тип ошибки.
Ни score, ни успешный rerank не означают подтверждённую истинность факта.

## Дополнения после аудита

SSO отложен пользователем. Управление проектными ролями/ACL теперь доступно в
API/UI и логируется. Чтение оригинала и экспорт ответа также создают события.
Для локальных API-клиентов можно задать `BANK_LOCAL_USERS_FILE`: JSON
`{случайный_токен_не_короче_24_символов: user_id}` с правами 0600. Файл хранится
вне Git, например в secrets/. Участие в проектах и роль выдаются отдельно.

`BANK_CLAMAV_HOST`/`BANK_CLAMAV_PORT` включает проверку всех загрузок через
ClamAV INSTREAM. Любой ответ кроме `stream: OK`, таймаут или сбой подключения
отклоняет загрузку. `BANK_REQUIRE_AV=true` запрещает загрузку и при отсутствии
конфигурации. Реальный банковский сканер ещё не предоставлен; тесты моделируют
clean/infected/outage. ClamAV не заменяет изоляцию парсера.

AES-256-GCM резервные копии создаются `manage.py bank-backup ... --key-file ...`.
32-байтовый ключ хранится отдельно от архива. Восстановление проверяет AEAD и
SQLite integrity_check до записи нового файла; существующий файл не заменяется.
Это шифрует **копию**, но не рабочую SQLite/FTS: нужен защищённый зашифрованный том.

Retention выполняется только явной командой владельца, по умолчанию — расчёт
списка. Удаляются оригиналы, canonical/derived индексы и связанные snapshots.
События аудита сохраняются. WAL, освобождённые страницы и внешние backup требуют
отдельной политики хранения и шифрования носителя; secure erase не заявляется.

API GigaChat ограничен rate limiter, бюджетом токенов вопроса, числом попыток и
общим временем. Проверяются окно контекста/резерв ответа. Разрешённые точные версии
модели можно закрепить `GIGACHAT_ALLOWED_MODEL_VERSIONS`; изменение версии тогда
блокирует публикацию ответа до регрессионной приёмки. Без настройки фиксируются
фактические версии, автоматического одобрения обновлений нет.
