# Варяг: точный поиск и Fast RAG v4

Продолжение этой итерации: [Fast RAG v5 — контекст выбранной модели и 50 документов](model-context-2026-10-16.md).
Лимиты v4 ниже сохранены как описание предыдущей версии.

Дата: 2026-10-16. Репозиторий: https://github.com/Daytonalove/Varag (private).

Исходное состояние сохранено отдельным коммитом, включая пользовательский
Fast RAG v3. Документ `Varyag_architecture_before_now.md` оставлен как история
передачи проекта. Нижеследующее описывает новую реализацию, а не обещание
полной точности или готовности корпоративного внедрения.

## Путь вопроса

```text
Чат → разрешение уточнения по предыдущим вопросам
    → ACL / доступная редакция документов
    → структурные коды и страницы + FTS5/BM25 + E5
    → RRF + локальный cross-encoder
    → резервирование каждого запрошенного кода
    → ограниченный контекст с точным снимком отправленного текста
    → один запрос GigaChat
    → локальная проверка ответа / дословные строки для точных кодов
    → ответ, цитаты, оригинал страницы
```

SQLite и существующие чаты сохранены. SSO не добавлялся. Автоматическая отправка
найденных фрагментов в GigaChat и простой интерфейс «Варяг» сохранены.

## Что изменено

1. **Структурный индекс.** `structural_keys` связывает код с версией документа,
   блоком, физической страницей и позицией в исходном тексте. Поиск `СМЭ.3`
   не совпадает с `СМЭ.30`. Кириллические/латинские омографы и OCR-ошибка `СМЭ.З`
   нормализуются только для поиска; оригинальный текст не переписывается.
   Ссылка на меру в обычном предложении не считается её определением.
2. **Независимый отбор.** Каждый запрошенный код получает отдельный путь отбора
   до реранкера и контекстного бюджета. Разные редакции не склеиваются. При
   нехватке бюджета ответ сообщает о ненайденном определении в контексте,
   не утверждая отсутствие меры в документе. Номер страницы означает физическую
   страницу PDF, а не напечатанный колонтитул.
3. **Привязка ответа.** Для вопроса с точным кодом показывается дословная строка
   определения. Неверное название соседней меры из ответа модели её не заменит.
   Это извлечение требования, а не автоматическое доказательство его применимости.
   Для общих ответов проверяются ссылки и числовые факты локально. Ошибка одного
   числового утверждения не удаляет независимые корректные утверждения.
4. **Один запрос генерации.** Fast не запускает смыслового LLM-верификатора,
   исправление JSON, анализ групп или повтор completion после 401. OAuth при
   необходимости отдельный; «один completion» не означает один HTTP-запрос всего.
   `RAG_ANSWER_MODE=audit` сохраняет прежний многоэтапный алгоритм.
5. **Ошибки и источники.** Timeout, HTTP-ошибки, blacklist, length и невалидный
   ответ различаются. При ошибке генерации нет потока поисковых кандидатов под
   видом цитат ответа. Журнал сохраняет кандидатов, стадию, причину, длительность
   и доступные usage. Счётчик последовательных сбоев сохраняется между вопросами.
6. **Бюджеты.** E5 разбивает длинный вход на окна в пределах собственного лимита
   и усредняет нормализованные векторы. Реранкер ограничен 384 токенами на пару.
   Для GigaChat используется консервативная оценка по UTF-8-байтам всего запроса
   с резервом для выхода и обрамления. Это верхняя оценка, а не точный токенизатор
   GigaChat; она может оставлять часть доступного контекста неиспользованной.
   Целые строки мер не обрезаются молча. Снимок цитаты и SHA-256 соответствуют
   именно отправленному тексту, даже если просмотр оригинала показывает больше.
7. **Геометрия PDF/OCR.** `page_layouts` хранит слова с координатами и кандидаты
   ячеек под явными числовыми заголовками. Табличное соответствие помечено
   `needs_review`; буквы без заголовков не превращаются в вывод об уровне защиты.
   Новая версия парсера — `bank-structure-3-table-geometry`.

## Миграция и настройка

При открытии старой базы автоматически добавляются таблицы схемы 7 и перестраивается
производный индекс кодов из существующих блоков. Оригиналы и сохранённые ответы
не переписываются. Геометрия старых страниц автоматически не восстанавливается:
для неё нужно повторное распознавание отдельной версией документа.

Перед миграцией сохранены согласованные копии обеих обнаруженных пользовательских
баз. Для нового запуска подготовлена отдельная `data/bank/varag.sqlite3` с более
свежей базой: 8 документов, 397 страниц, 18 ответов. SQLite integrity_check: OK.
Эти файлы, ключи, локальная конфигурация и веса моделей не публикуются в GitHub.

Локальный запуск этой копии из каталога проекта:

```bash
BANK_DATABASE=data/bank/varag.sqlite3 .venv/bin/python manage.py bank --api-port 8767 --ui-port 8503
```

Для обычной новой установки достаточно `manage.py bank`; путь базы задаётся
`BANK_DATABASE`. Файл `.env.example` описывает переменные и сам не загружается.
По умолчанию Fast использует 8 источников, 10 000 символов контекста, до 2 400
символов обычного источника и 2 500 выходных токенов. Полная строка меры может
превышать обычный лимит источника, оставаясь внутри общего бюджета.

При переносе обнаружен устаревший ключ в прежней рабочей папке (OAuth 401).
Активная локальная конфигурация перенесена из пользовательской папки Fast RAG v3;
прежние ключи и конфигурация сохранены. Успешные новые проверки выполнены моделью
`GigaChat-2:2.0.30.01`. Ключ не входит в отчёты.

## Проверки

- 146 автоматических тестов: права доступа, редакции, история, коды, ложные
  префиксы и обозначения стандартов, контекст, ошибки, сохранение источников,
  реальный PDF и OCR изображения, интерфейс и очереди.
- 10/10 локальных диагностических проверок прежнего контура.
- `precision-synthetic.json`: 5/5 структурных сценариев с реальными моделями.
  В длинном тесте реальный вход реранкера достиг 381/384 токенов, E5 — 504/512.
- `precision-live.json`: 5/5 синтетических сценариев через GigaChat, один completion
  на вопрос, включая ненайденный код и одинаковый код в разных стандартах.
- `precision-workspace-live.json`: загрузка трёх документов через API, обработка
  очереди, реальный гибридный поиск с реранкером и два ответа GigaChat в диалоге.
  Всего два запроса генерации; временная база, пользовательские данные не менялись.
- `precision-real-local.json`: 5/5 локальных поисковых сценариев на копии реального
  корпуса: СМЭ.3, ЗСВ.5, УЗП.21, совместный запрос и отрицательный пример.
  Предыдущий поиск также нашёл положительные примеры в этом снимке базы.
  Эти результаты подтверждают регрессию, но не доказывают рост recall относительно
  прежней версии. Новая защита касается прежде всего использования найденной строки.

Проверки воспроизводятся через `unittest`, `scripts/evaluate_precision.py` и
его опцию `--live`. Последняя отправляет только встроенные синтетические файлы.

## Оставшиеся задачи — без объявления их выполненными

| Приоритет | Состояние | Следующая работа / критерий |
|---|---|---|
| P0: точные коды и привязка | Реализовано, регрессии пройдены | Расширять корпус OCR-вариантов и измерять ошибки извлечения |
| P0: ошибки генерации | Реализовано | Наблюдать ошибки и стоимость на реальной эксплуатации |
| P1: таблицы | Частично | Объединённые ячейки, переносы строк/заголовков между страницами; сверка с разметкой эксперта |
| P1: документы и редакции | Частично | Сейчас ГОСТ определяется по названию/метаданным/началу документа; нужен подтверждённый каталог обозначений и редакций, особенно для сборников |
| P1: память | Реализованы регрессии | Детерминированный resolver не понимает все формулировки, нужны новые диалоговые кейсы |
| P1: входные лимиты | Реализовано | Оценить потерю качества усреднения E5 на длинных запросах и консервативного бюджета контекста |
| P2: независимая приёмка | Не выполнена | Новые документы и экспертные ответы, не использованные при настройке; recall, точность цитат, корректность выводов и latency/cost |
| P2: корпоративное внедрение | Вне текущей итерации | Политики доступа/хранения, эксплуатация; SSO отложен по указанию пользователя |
| P2: нормативный аудит | Вне задачи чата | Отдельная методика применимости, свидетельства выполнения и ручное утверждение |

Общий текстовый вывод модели по-прежнему не является доказанным только потому,
что у него есть существующая ссылка. OCR может неверно распознать исходную строку.
Сравнение мер по уровням защиты нельзя считать проверенным, пока строки, колонки
и заголовки не сверены с оригиналом.
