# Документы и ответы — проект для VS Code

**Актуальная банковская система:** запуск `.venv/bin/python manage.py bank`,
интерфейс http://127.0.0.1:8502, [инструкция](README.md).
F5 и задача «RAG: запустить» запускают именно её. Инструкция ниже относится
к исходному пилоту (`manage.py run`, порт 8501), сохранённому для совместимости.

Локальный пилот для macOS с Apple Silicon: Streamlit-интерфейс, Flask API, OCR, гибридный поиск и ответы через GigaChat. Docker, JupyterHub и Colab не нужны. Интерфейс открывается в браузере; VS Code используется для установки, запуска, изменения кода и отладки.

Локальный код и зависимости — open source; `openai` и `tiktoken` не используются и запрещены при установке/запуске. GigaChat — внешний API, который требует вашего ключа и доступной квоты. Генерация не выполняется локально.

См. [результаты испытания](evaluation/REPORT.md) и [команды повторного запуска](evaluation/README.md). ## Первый запуск на macOS

1. Распакуйте архив. В VS Code выберите **File → Open Folder… → document-rag-vscode**. Открывать нужно всю папку, не отдельный Python-файл.
2. Установите рекомендованные расширения **Python** и **Python Debugger** из Microsoft Marketplace. Откройте **Terminal → New Terminal**. Все команды ниже выполняются из папки проекта.
3. Установите Python и системные компоненты OCR через [Homebrew](https://brew.sh/), если Homebrew уже установлен:

```bash
brew install python@3.12 tesseract tesseract-lang poppler
tesseract --list-langs
```

В списке должны быть `rus` и `eng`. Если `brew` отсутствует, сначала установите его по официальной инструкции на сайте Homebrew. GPU не нужен. Желательно 8 GB RAM и несколько GB свободного диска для окружения, модели и базы; скорость зависит от процессора и документов. Этот набор закреплённых версий проверяется на Apple Silicon. Для Intel Mac потребуется отдельно подобрать совместимые версии PyTorch/Python; эта сборка на Intel Mac не проверена.

4. Создайте изолированное окружение и скачайте модель поиска:

```bash
python3.12 scripts/bootstrap.py
.venv/bin/python manage.py download-model
```

Установка пишет лог в `bootstrap.log`; глобальные Python-пакеты не изменяются. Скрипт сначала проверяет план зависимостей, затем устанавливает пакеты. На Linux используется CPU-репозиторий PyTorch; на macOS вычисления также явно выполняются на CPU. Модель `intfloat/multilingual-e5-small` скачивается с закреплённой ревизией. Во время обычного поиска загрузки из Hugging Face отключены (`local_files_only=True`).

5. Настройте GigaChat:

```bash
.venv/bin/python manage.py configure
```

- Введите **Authorization key**, не временный Access token и не строку с префиксом `Basic`. Ввод скрыт. Ключ сохраняется в `secrets/gigachat.key` с правами `0600`.
- По умолчанию используется **GigaChat-2**. Можно выбрать другой ID из списка доступных вашему аккаунту.
- Укажите путь к PEM-файлу доверенных сертификатов, если они необходимы для подключения. См. раздел ниже. Enter оставляет текущие настройки.
- Для физического лица установлен scope `GIGACHAT_API_PERS`. Для другого типа аккаунта измените `gateway.scope` в `config.json` согласно настройкам аккаунта.
- Альтернатива ключевому файлу — переменная `GIGACHAT_CREDENTIALS`; она имеет приоритет. Не добавляйте ключ в исходники или конфигурации VS Code.

6. Проверьте окружение и API:

```bash
.venv/bin/python manage.py doctor
.venv/bin/python manage.py doctor --live
```

Первая команда проверяет CPU-сборку, отсутствие запрещённых пакетов, OCR/языки, локальную модель и доступность CA-файла. Вторая дополнительно проверяет OAuth, `/models` и наличие выбранной модели. Она **не проверяет генерацию** и доступный баланс для ответа.

7. Загрузите учебные документы и запустите приложение:

```bash
.venv/bin/python manage.py demo
.venv/bin/python manage.py run
```

Откройте **http://127.0.0.1:8501**. Flask работает на `127.0.0.1:8765`; это API, отдельной HTML-страницы на нём нет. Вызовы Flask требуют локальный служебный токен, который Streamlit подставляет автоматически.

Чтобы остановить оба сервера, нажмите **Ctrl+C** в терминале. Не запускайте одновременно второй экземпляр приложения с той же базой. Повторный запуск сохраняет документы и чаты.

## Запуск и отладка в VS Code

После установки выполните **Python: Select Interpreter** в Command Palette и выберите `.venv/bin/python`. Затем откройте **Run and Debug**, выберите **RAG: Flask + Streamlit** и нажмите **F5**. Конфигурация включает отладку дочерних процессов, поэтому точки останова можно ставить в `document_rag/api.py`, `engine.py`, `provider.py` и `ui.py`.

Остановите прежний запуск перед F5. Для остановки выберите управляющую сессию `manage.py` и **Stop Debugging**; можно также нажать Ctrl+C в её терминале. **Terminal → Run Task…** содержит задачи установки, загрузки модели, настройки ключа, диагностики, примеров, selftest и запуска.

Если порты заняты:

```bash
.venv/bin/python manage.py run --api-port 8766 --ui-port 8502
```

При изменении `config.json` остановите и снова запустите приложение. Для отдельной конфигурации можно установить `RAG_CONFIG=/абсолютный/путь/config.json`; относительные пути внутри неё отсчитываются от её каталога.

## Сертификаты GigaChat

При ошибке TLS воспользуйтесь [официальной инструкцией GigaChat по сертификатам](https://developers.sber.ru/docs/ru/gigachat/certificates). Скачайте указанные там корневой и промежуточный сертификаты в PEM из официальных источников. Объедините их в файл, например:

```bash
mkdir -p secrets
cat /путь/к/root.pem /путь/к/sub.pem > secrets/gigachat-ca.pem
.venv/bin/python manage.py configure
```

В диалоге укажите `secrets/gigachat-ca.pem`. Проверка TLS остаётся включённой; дополнительных сертификатов достаточно для приложения, менять системное хранилище не требуется. Имена скачанных файлов могут отличаться от примера. Не отправляйте ключ или полный конфигурационный файл в чат для диагностики.

## Использование интерфейса

1. Загрузите файлы слева и нажмите **Загрузить и обработать**. Дождитесь завершения; первый запуск модели и OCR больших документов может занять время.
2. Выберите **Источники ответа**. Вопросы всегда ограничены выбранными документами.
3. Во вкладке **Проверить поиск** задайте вопрос: здесь видны найденные фрагменты без обращения к GigaChat.
4. В **Чате** задайте тот же вопрос. Для двух учебных файлов включите **Сравнить выбранные документы** и спросите: «Как изменился срок поставки по договору П-17?» Ожидается изменение с 10 до 15 рабочих дней с цитатами из договора и допсоглашения.
5. Раскройте ссылки на источники, чтобы прочитать цитаты. В **Библиотеке** можно скачать оригинал или удалить документ вместе со связанными диалогами. В **Истории** можно продолжить сохранённый диалог после перезапуска.
6. Во вкладке **Состояние** доступна проверка подключения и списка моделей.

Смена выбранных документов или режима сравнения начинает новый диалог. Для уточняющего вопроса приложение использует до двух предыдущих пар вопрос/ответ и делает отдельный вызов GigaChat для переформулирования запроса. При замене документа его старая версия не используется для уточнения новых вопросов; прежние ответы остаются снимками старых источников.

## Как устроен RAG

Это **гибридный RAG по фрагментам с историей диалога и проверкой цитат**:

```text
PDF/DOCX/изображение/текст
  → извлечение текста / OCR Tesseract
  → фрагменты до 700 символов с перекрытием
  → E5-эмбеддинги + SQLite FTS5

вопрос → [уточнение по истории] → поиск BM25 + векторное сходство
  → объединение рангов RRF → ограниченный набор фрагментов
  → GigaChat → JSON с утверждениями и цитатами
  → проверка цитат/источников → ответ или отказ
```

Локальная модель поиска кодирует документы с префиксом `passage:`, вопрос — `query:`. Векторы нормализованы, ранжирование использует скалярное произведение. Лексический поиск FTS5 полезен для точных названий и чисел; морфологического русского анализатора в нём нет. Два рейтинга объединяются через Reciprocal Rank Fusion. Векторный поиск выполняет полный перебор внутри выбранных документов: для пилота это проще, но не рассчитано на большую корпоративную базу.

При сравнении выбираются до трёх фрагментов из каждого из 2–8 документов. Если модель не привела подтверждения из каждого документа, приложение один раз просит исправить ответ. При повторной ошибке ответ отклоняется. Само наличие цитаты не доказывает, что логический вывод модели верен. Это не GraphRAG, не агентная система и не гарантированная полная сверка документов.

OCR, извлечение, поиск и база работают локально. В GigaChat уходят вопрос, отобранные фрагменты и, при продолжении диалога, короткая история. Оригиналы файлов для генерации не отправляются. Интернет нужен при установке пакетов/модели и для GigaChat.

## Хранение и резервная копия

| Путь | Содержимое |
|---|---|
| `data/library.sqlite3` | Оригиналы документов, извлечённые фрагменты, векторы, история вопросов/ответов и цитаты |
| `data/library.sqlite3-wal`, `-shm` | Служебные файлы SQLite во время работы |
| `data/server.token` | Служебный токен для локального Flask API |
| `models/multilingual-e5-small/` | Локальная модель поиска |
| `secrets/gigachat.key` | Authorization key GigaChat |
| `config.json` | Настройки приложения, пути к секретам, ID модели |

Данные остаются после закрытия вкладки, VS Code и перезагрузки компьютера. База не зашифрована приложением. Файл с тем же именем заменяет оригинал и индекс атомарно; если извлечение или индексация не удались, прежняя версия сохраняется. История хранит снимки старых цитат. Удаление документа удаляет связанные чаты в текущей базе; уже сделанные резервные копии остаются отдельными файлами.

Для согласованной резервной копии SQLite:

```bash
.venv/bin/python manage.py backup backups/library-2026-10-14.sqlite3
```

Команда требует новое имя файла и включает оригиналы, индекс и историю; ключ и модель в копию не входят. Для восстановления остановите приложение, переместите **весь** текущий каталог `data` в отдельную папку, создайте пустой `data` и поместите копию как `data/library.sqlite3`. Служебный токен будет создан заново. Не смешивайте новую базу со старыми файлами `-wal`/`-shm`. Используйте те же настройки и ревизию модели поиска. Можно вместо этого указать новый путь в `storage.database`.

`config.json`, `data`, `models`, `secrets`, `.venv` исключены из Git. В архиве проекта нет ключей, личных документов и скачанной модели. База старого Colab-пилота автоматически не мигрируется: для нового проекта загрузите исходные документы заново.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python manage.py selftest
```

Автотесты используют временные базы и подставные ответы GigaChat: проверяют сравнение и повторную попытку, отказ от выдуманных цитат, историю/смену источников, замену/удаление документов, резервную копию, OAuth-кэш и обновление по 401, а также работу Streamlit через AppTest вместе с Flask.

`selftest` действительно распознаёт созданные изображение и сканированный PDF на русском, затем проверяет локальный семантический поиск по вопросу без совпадающих ключевых слов. Рабочая библиотека не изменяется, GigaChat не вызывается. Для Linux нужен шрифт DejaVu Sans; на macOS используется Arial.

## Ограничения и частые ошибки

- Это локальное приложение для одного владельца. Flask development server, общий каталог данных и последовательная обработка не предназначены для 100 пользователей или публичного размещения. Серверы слушают только `127.0.0.1`.
- Поддержаны PDF, DOCX, UTF-8 TXT/MD, PNG/JPG/TIFF. Старый `.doc` преобразуйте в DOCX/PDF. Максимум 25 MiB на файл, PDF — до 200 страниц, без шифрования.
- Для PDF OCR включается при малом количестве извлечённого текста. Смешанные страницы с картинками и текстом могут быть распознаны не полностью: при необходимости установите `ocr.force_pdf_ocr=true` и загрузите документ заново. Колонки, таблицы, числа и плохие сканы требуют проверки по оригиналу.
- Для DOCX приводятся номера блоков, не страниц. Встроенные рисунки, сноски и сложная разметка не обрабатываются полноценно.
- Фрагменты и контекст ограничены по символам; модель поиска дополнительно проверяет свой токенный лимит. Если он превышен, уменьшите `retrieval.chunk_characters` и создайте новый индекс. Весь большой документ за один запрос не анализируется.
- При изменении режима поиска, модели/ревизии или размера фрагментов укажите новый `storage.database` и загрузите документы заново. Это предотвращает смешивание несовместимых индексов.
- `HTTP 401`: ошибка авторизации, а не автоматически неправильный ключ. OAuth и запрос модели диагностируются отдельно. `402`: проверьте баланс/пакет модели. `404`: адрес или ID модели. Успешный `/models` ещё не означает, что генерация доступна.
- Модель отсутствует: выполните `doctor --live`, выберите ID из выведенного списка в `gateway.model`, перезапустите приложение. Старое имя `GigaChat` намеренно не используется по умолчанию.
- Ошибка TLS: настройте `gateway.ca_file`; не отключайте проверку сертификатов.
- `ModuleNotFoundError`: выбран не тот Python. Используйте `.venv/bin/python` и выберите этот интерпретатор в VS Code.
- Ошибка `ensurepip`: установщик умеет создавать venv без pip и устанавливать pip через родительский интерпретатор. Запускайте его через установленный Python 3.12, а не системный Python 3.14.
- Отказ «нет подтверждений из каждого документа»: сначала проверьте фрагменты во вкладке поиска. Цитаты не подставляются искусственно, проверка не отключается.

## Файлы для разработки

- `manage.py` — установка настроек, диагностика, запуск/остановка, копия базы.
- `scripts/bootstrap.py` — изолированное Python-окружение и аудит зависимостей.
- `ui.py` — Streamlit: загрузка, выбор источников, чат, история, оригиналы.
- `document_rag/api.py` — Flask-маршруты, локальная авторизация и очередь обработки.
- `document_rag/engine.py` — SQLite, индекс, гибридный поиск и диалоги.
- `document_rag/extraction.py` — PDF/DOCX/текст/OCR и фрагменты.
- `document_rag/provider.py` — GigaChat OAuth/REST через стандартную библиотеку Python.
- `document_rag/answering.py` — формат ответа, проверка точных цитат и покрытия документов.

Исходники проекта распространяются по MIT; лицензии сторонних компонентов и модели действуют отдельно.
