# Банковский аудит — интеллектуальный поиск на SQLite

**Статус:** работающий локальный поиск/RAG; после аудита исправлены сравнение
операторов/сроков, исторические версии, схема ответа, реестр и экспорт.
[Исправления, проверки и открытые условия приёмки](docs/remediation-2026-10-15.md).
Полное соответствие банковскому ТЗ пока не объявляется. SSO отложен пользователем.

Приложение загружает PDF/сканы, извлекает и индексирует текст локально,
отвечает на вопросы через GigaChat, сохраняет проверяемые цитаты и историю.
SQLite остаётся основной БД по решению пользователя. PostgreSQL/Redis/S3 для
этого сценария не нужны. Это локальный однопользовательский MVP, не банковская
production-система с SSO и банковской экспертной приёмкой. API также поддерживает
дополнительных локальных пользователей через защищённый BANK_LOCAL_USERS_FILE;
стандартный UI использует локальную сессию аудитора.

## Запуск и работа

При первом клонировании (Python 3.12, macOS/Linux):

```bash
git clone https://github.com/Daytonalove/document-rag-vscode.git
cd document-rag-vscode
python3.12 scripts/bootstrap.py
```

Для OCR установите Poppler и Tesseract с `rus+eng` (macOS: `brew install poppler
tesseract tesseract-lang`; Ubuntu: `apt install poppler-utils tesseract-ocr
tesseract-ocr-rus fonts-dejavu-core`). Затем загрузите локальные модели:

```bash
.venv/bin/python manage.py download-model
.venv/bin/python scripts/setup_reranker.py
```


```bash
.venv/bin/python manage.py bank
```

Откройте http://127.0.0.1:8502. API работает на 127.0.0.1:8766.
В VS Code F5 («Банковский аудит: API + интерфейс») и задача «RAG: запустить»
используют эту же команду. Порт 8501 относится к исходному пилоту.

1. В боковой панели откройте «Подключение GigaChat», нажмите «Проверить подключение».
   На исходной машине ключ хранится на сервере. На новом компьютере задайте
   `GIGACHAT_KEY_FILE`, `GIGACHAT_SCOPE`, `GIGACHAT_MODEL`, `GIGACHAT_CA_BUNDLE`;
   секреты и модели в Git не включены. Scope/model/CA также берутся из config.json
   либо GIGACHAT_* переменных окружения. Ключ в браузер не передаётся.
   Путь к файлу ключа: `GIGACHAT_KEY_FILE`, затем `gateway.key_file` в config.json,
   затем `secrets/gigachat-bank.key`. `manage.py configure` обновляет файл из config.json.
2. Включите разрешение отправки вопросов и разрешённых фрагментов, нажмите
   «Применить настройку GigaChat». Решение сохраняется в SQLite. По умолчанию отправка выключена.
3. Создайте проект. Выберите файлы, отметьте разрешение анализа этих файлов через
   GigaChat и загрузите. Для ранее загруженных файлов политика меняется в «Управление».
4. Дождитесь статуса ready/ready_with_warnings; таблица обновляется автоматически.
5. Для локальной выдачи откройте «Интеллектуальный поиск»: введите запрос, при
   необходимости выберите документы и количество результатов. GigaChat не нужен.
6. Откройте «Вопросы и источники», включите «Ответить через GigaChat» и задайте вопрос.
   Ответ готовится в фоне; его статус и результат обновляются автоматически.
   Уточнения отправляйте в выбранный диалог, другую тему начинайте с «Новый диалог».

При необходимости укажите дату проверки в формате YYYY-MM-DD. Приведённые значения
и условия сопровождаются ссылками [1], [2] на список источников. Можно открыть
оригинальную страницу с координатной подсветкой, сверить OCR, сохранить заключение
и скачать JSON, HTML или прямой PDF-отчёт с кириллицей.

Во вкладке «Реестр и управление» доступны подтверждение метаданных, связи
документов с пунктом-основанием, роли, ACL, показатели вызовов и срок хранения.

Если внешняя отправка запрещена, доступен локальный поиск по документам с точными
выдержками. Он явно отличается от смыслового ответа GigaChat. Ошибки модели или
отклонённые утверждения не выдаются за успешный полный анализ.

## Что работает

- Проекты, пакетная загрузка, версии и оригиналы по SHA-256, постраничный PDF/OCR,
  многостраничный TIFF. Обработка вынесена в отдельный процесс с лимитом времени.
- SQLite WAL, сохраняемые очереди загрузок/вопросов/индексов и восстановление
  после перезапуска. Повтор запроса с тем же Idempotency-Key не создаёт второй ответ.
- Полный текст, FTS5, денежные значения, локальные e5 embeddings, соседние/родительские
  пункты и явные ссылки на пункты внутри документа, независимый поиск альтернатив.
- Глобальное RRF-объединение выдач, локальный cross-encoder реранкер, окна длинных
  блоков, отдельный поисковый экран/API, фильтр документов, оценки и оригиналы.
- Содержательные ответы GigaChat: JSON Schema, проверка ID/цитат/чисел, отдельная
  проверка смысловой поддержки утверждений; ограниченные повторы, разбиение при 422.
  Модель выбирает ссылки на фрагменты; дословные цитаты подставляет сервер из оригинального
  извлечённого текста. Неподтверждённые утверждения исключаются с предупреждением.
- Контекст диалога, дата проверки, независимые предупреждения о разных лимитах,
  сохранённые источники/версия корпуса/охват и технический аудит вызовов без промптов.
- Повторное распознавание, исправление OCR отдельной редакцией, перестроение
  смыслового индекса без повторной загрузки, резервная копия SQLite.
- Типизированные даты/суммы/сроки/проценты, точные индексы и фильтры реестра,
  включаемый claims-index, исторический поиск и сравнение норм между группами.
- Реальные координаты PDF/OCR, постраничный прогресс, просмотр кадров TIFF,
  прямой PDF; ClamAV hook, аудит экспорта и шифрованные резервные копии.

## Реранкер

Используется локальный `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`,
ревизия `1427fd652930e4ba29e8149678df786c240d8825`, Apache-2.0.
[Карточка модели](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1)
указывает поддержку русского языка. Веса safetensors (~470 МБ) и токенизатор
хранятся в `models/mmarco-mMiniLMv2-L12-H384-v1`, контрольные суммы проверяются
при запуске. Загрузка во время пользовательского запроса запрещена;
`local_files_only=True`, `trust_remote_code=False`, CPU, batch 8.

Путь: FTS5/BM25 + e5 → RRF по всему доступному корпусу → до 160 кандидатов из
независимых поисковых путей → cross-encoder → сохранение альтернатив/исключений
и связанного контекста → бюджет источников → GigaChat или локальная выдача.
Пары оцениваются окнами до 384 токенов, до 12 окон на блок; усечение отражается
в манифесте. Оценка модели — **релевантность**, не вероятность истинности.

Реранкер обязателен при обычном запуске. Если файлы отсутствуют/повреждены,
backend даёт инструкцию установки, не делает вид, что модель включена.
`BANK_RERANKER_MODE=disabled` — явный режим без модели. При runtime-сбое выдача
сохраняется с предупреждением и `reranker.status=failed`. `health` сообщает
наличие модели, каждый результат — фактический статус выполнения.

## Поиск и обслуживание

Режим auto включает установленную локальную модель `models/multilingual-e5-small`.
Новых сетевых загрузок при обработке документов нет. При отсутствии модели работает
лексический поиск с явной отметкой. Установка модели в существующем окружении:

```bash
.venv/bin/python manage.py download-model
```

Для принудительного режима: BANK_RETRIEVAL_MODE=hybrid или lexical.
При запуске гибридного режима старые lexical-only документы автоматически ставятся
на построение vectors. Кнопка «Перестроить смысловой индекс» выполняет это вручную.
«Повторить распознавание» создаёт новую версию извлечения, сохраняя старые источники.
Исправление текста доступно после «Открыть страницу и текст».

```bash
.venv/bin/python manage.py bank-backup data/backups/bank-2026-10-15.sqlite3
```

Для шифрованной копии передайте `--key-file /защищённый/путь/backup.key`
(файл из 32 случайных байт). Восстановление в **новый** файл:
`manage.py bank-restore copy.encrypted restored.sqlite3 --key-file ...`.
Рабочая SQLite требует зашифрованного тома; backup-шифрование не меняет её формат.

Файл резервной копии не должен существовать. Для восстановления остановите приложение
и задайте BANK_DATABASE=/полный/путь/к/копии.sqlite3 при следующем запуске.
Исходная старая библиотека `data/library.sqlite3` не меняется.

## Проверки

Последняя проверка: 127 локальных тестов, 10/10 диагностических проб и 5/5
синтетических live-сценариев GigaChat. Все 98 пунктов ТЗ учтены в
[матрице](docs/requirements-status.md), включая открытые ограничения.

Без внешнего API:

```bash
.venv/bin/python -m unittest discover -s tests -q
```

Локальная проверка качества поиска (30 синтетических документов, 40 вопросов;
реальные e5 и cross-encoder, без внешнего API):

```bash
.venv/bin/python scripts/evaluate_bank_search.py
```

Отчёт: `evaluation/results/bank-search-reranked.json`. Контрольные пороги:
Recall@5 ≥ 0.90, MRR@10 ≥ 0.80, сохранение обязательных альтернатив, nDCG@10
не хуже гибридной базы. Это регрессионный набор, не банковская приёмка.

Только синтетические документы, реальный GigaChat, временная SQLite, асинхронные
вопросы и уточнение в диалоге:

```bash
.venv/bin/python scripts/bank_gigachat_smoke.py --scope GIGACHAT_API_PERS --model GigaChat-3-Pro --workspace-e2e
```

Синтетический проект для интерфейса: `.venv/bin/python scripts/bank_demo.py`.
Он не включает разрешение внешней отправки автоматически.

Технические настройки: `.env.example` (справочник; .env не загружается автоматически).
EXTERNAL_LLM_APPROVED из окружения задаёт состояние при запуске, иначе используется
сохранённое решение UI. GIGACHAT_AUTH_KEY либо GIGACHAT_KEY_FILE переопределяют
серверный файл secrets/gigachat-bank.key. TLS всегда проверяется.

## Исходный пилот

Локальный пилот для macOS с Apple Silicon: Streamlit-интерфейс, Flask API, OCR, гибридный поиск и ответы через GigaChat. Docker, JupyterHub и Colab не нужны. Интерфейс открывается в браузере; VS Code используется для установки, запуска, изменения кода и отладки.

Локальный код и зависимости — open source; `openai` и `tiktoken` не используются и запрещены при установке/запуске. GigaChat — внешний API, который требует вашего ключа и доступной квоты. Генерация не выполняется локально.
