# Результаты проверки RAG на ГОСТ 57580 и 50 документах

Дата: 14 октября 2026 года. Среда: macOS, Apple Silicon, Python 3.12, CPU, multilingual-e5-small. Проверены приложение и поиск по содержимому документов. Оценка соответствия реальной финансовой организации не проводилась.

## Результат

Все 50 файлов загружены через обработчик Flask, включая два ГОСТ, длинные PDF, Word и сканы. Исходная версия пропускала часть нужных источников и конкретных пунктов стандарта. После исправления поиск вернул все ожидаемые документы в 24 из 24 контрольных вопросов, где источники известны.

**Это показатель полноты поиска на небольшом искусственном наборе, а не точность ответов GigaChat и не гарантия нахождения всех противоречий.** Вызовы генерации GigaChat не выполнялись: ключ отсутствовал в среде испытания. Скрипт для их воспроизводимой проверки включён в проект.

## Набор и методика

В наборе 2 стандарта, 20 TXT, 12 текстовых PDF по 30 страниц, 8 одностраничных DOCX и 8 двухстраничных сканированных PDF. Суммарно 470 страниц PDF, 8 страниц Word, размер всех 50 файлов 5.89 MiB. Сканам добавлены наклон, сниженный контраст и размытие; рукописные документы, фотографии с тяжёлыми искажениями и плохие многостолбцовые сканы не моделировались.

Контрольные вопросы и ожидаемые источники зафиксированы в `manifest.json`. Испытание состоит из последовательной загрузки одним клиентом, поиска по всей базе, проверки извлечения контрольных чисел, негативных случаев и проверки упаковки найденных источников в контекст ответа. Нет 50 параллельных пользователей. Начальный и исправленный поиск проверялись на одинаковых вопросах. Исправления разрабатывались на этом наборе, поэтому он является регрессионным, а не независимым тестовым набором для оценки обобщения.

| Проверка | Исходная версия | Исправленная версия |
|---|---:|---:|
| Загруженные документы | 50/50 | 50/50 |
| Фрагменты | 1254 | 1254 |
| Все ожидаемые документы найдены в первых 8 результатах | 22/24 | 24/24 |
| Средняя доля найденных ожидаемых документов | 95,8% | 100% |
| Контрольные текстовые признаки в 6 вопросах по ГОСТ | 4/6 | 6/6 |
| Все ожидаемые документы сохранены в конечном контексте | Не измерялось | 24/24 |
| Контрольные числа в сканированных файлах | 8/8 | 8/8 |

Вопрос без ответа исключён из доли покрытия: у него нет ожидаемого источника. Вопрос с недоверенной инструкцией входит в проверку поиска текста вложения; это **не** подтверждение устойчивости генерации к такой инструкции.

## Найденные ошибки и изменения кода

1. **Пропуск точного пункта ГОСТ.** Обычная токенизация разрывала номера `6.7` и `6.13`, а одинарные цифры отбрасывались. Смысловая близость не гарантировала попадания нужного пункта в первые результаты. Добавлен поиск точных ссылок с приоритетом начала пункта. Ссылка `6.13` не подменяется `6.13.1`.
2. **Один документ занимал почти весь контекст.** В вопросе о мобильных устройствах терялась производственная политика; в вопросе о компенсирующих мерах отсутствовал один из двух ГОСТ. Добавлено распределение результатов: сначала до двух фрагментов на документ, затем заполнение оставшихся мест. При выборе одного документа ограничение не действует.
3. **Ошибки букв и цифр в текстовом слое.** Добавлены поисковые варианты кодов мер для похожих латинских/кириллических букв и `З/3`, `О/0` в цифровой части. Исходные цитаты не изменяются.
4. **Обрезанный пункт или строка таблицы.** Для точной ссылки добавляются до двух следующих фрагментов с той же страницы. Это сохраняет больше контекста, но не восстанавливает табличную структуру автоматически.
5. **Неочевидный охват.** API и интерфейс теперь показывают, сколько из выбранных документов действительно попало в контекст, и перечисляют не представленные документы. Таблицы и формулы PDF сопровождаются предупреждением о проверке по оригиналу.

Новые настройки не меняют формат SQLite и не требуют переиндексации только ради улучшенного ранжирования. Чтобы новые предупреждения обработки появились для уже загруженных PDF, их нужно загрузить повторно.

## Что проверено по ГОСТ

Проверен поиск мер по учётным записям, уровней защиты, источников свидетельств, неоцениваемых областей и связи компенсирующих мер с их оценкой. Для контроля номеров использованы страницы PDF: ГОСТ 57580.1 — 12 и 15; ГОСТ 57580.2 — 9 и 10. Номера страниц PDF отличаются от напечатанных внутри стандарта.

ГОСТ 57580.2 предусматривает работу со свидетельствами разных типов; наличие текста политики само по себе не подтверждает фактическое выполнение меры. Пункт 6.12 связывает оценку компенсирующих мер с положением 6.4 ГОСТ 57580.1. Это проверенная перекрёстная ссылка, не обнаруженное противоречие. Полная экспертиза всех положений двух стандартов на взаимную непротиворечивость не выполнялась. Источники, редакции и контрольные суммы приведены в [инструкции испытания](README.md#источники-стандартов).

## Производительность и обработка ошибок

В заключительном прогоне загрузка и индексация заняли 23.6 с. Медиана локального поиска составила 0.076 с, максимум среди 25 вопросов — 0.109 с. Размер основной базы — 18.34 MiB. Пиковый RSS процесса Python — около 1.11 GiB; память дочерних процессов OCR и остальной системы в это число не входит.

Это одиночные измерения на конкретном компьютере, с заранее установленной моделью и небольшими синтетическими файлами. Они не прогнозируют скорость 50 полноразмерных сканов по 30 страниц, сетевые задержки API или работу 100 пользователей. Холодный старт модели при отдельном повторном запуске только поиска занял до 2,90 с на первом вопросе.

Повреждённый PDF и пустой TXT отклонены с ошибкой задания; неподдерживаемый формат отклонён HTTP 400. Процесс продолжил работу. Попытка включить режим сравнения сразу для 50 файлов явно отклонена HTTP 400: этот режим поддерживает 2–8 документов.

37 автоматических тестов ядра, Flask, клиента GigaChat, новых правил поиска и Streamlit прошли. Реальные ответы внешнего API, отказ от галлюцинаций на отсутствующем факте и устойчивость к инструкции внутри вложения остаются непроверенными.

## Что пока нельзя обещать

- Обычный вопрос по 50 выбранным документам использует только отобранные фрагменты. Он не проверяет все 50 документов целиком.
- Полный автоматический поиск всех противоречий между всеми пунктами не реализован. Сравнение отдельных выбранных документов остаётся ограниченным поисковым контекстом.
- Система не восстанавливает надёжно таблицы уровней защиты и математические формулы. Их нельзя использовать для автоматического расчёта оценки соответствия без отдельной структурированной проверки.
- Наличие дословной цитаты проверяется программно; логическая правильность вывода — нет.
- Нет подтверждённой готовности к корпоративной многопользовательской эксплуатации.

Для полноценной проверки по ГОСТ следующим этапом нужна матрица «мера → применимость/уровень → подтверждающие документы и технические свидетельства → расхождение → решение проверяющего». Для поиска противоречий необходимо учитывать объект, срок действия, иерархию документов, исключения и границы числовых требований. Для текущего пилота подготовлен сценарий живой проверки восьми ответов GigaChat с сохранением цитат и результатов для ручной оценки.
