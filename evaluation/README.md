# Проверка двух ГОСТ и набора из 50 документов

Готовый отчёт: [REPORT.md](REPORT.md). Машинные результаты находятся в `results/`.

В архив включены 48 искусственных файлов. Две открытые копии стандартов загружаются отдельно с проверкой SHA256. После этого в `evaluation/corpus` будет ровно 50 документов. Ключ GigaChat для загрузки стандартов, индексации и проверки поиска не нужен.

## Повторить испытание

Команды выполняются из корня проекта после установки зависимостей и модели по основному README:

```bash
.venv/bin/python scripts/fetch_standards.py
.venv/bin/python scripts/evaluate_corpus.py \
  --corpus evaluation/corpus \
  --manifest evaluation/manifest.json \
  --database data/evaluation.sqlite3 \
  --report evaluation/results/my-run.json
```

Используйте новое имя базы при повторной полной загрузке. Для проверки поиска в уже созданной тестовой базе добавьте `--reuse`. Рабочая `data/library.sqlite3` не изменяется. Файлы проходят через обработчик загрузки Flask и фоновую очередь, однако HTTP-транспорт заменён Flask test client; это проверка кода API, не сетевой нагрузочный тест.

Скрипт проверяет 25 вопросов: 24 имеют ожидаемые источники, один специально не имеет ответа в наборе. Доля найденных источников не является долей правильных ответов модели. Наличие фрагментов для вопроса без ответа не считается успешной проверкой отказа модели.

Чтобы открыть тестовую базу в интерфейсе, после завершения испытания установите в `config.json`:

```json
"storage": {"database": "data/evaluation.sqlite3"}
```

Затем запустите `manage.py run`. После испытания верните путь рабочей базы. Не запускайте тесты и интерфейс одновременно с одной и той же базой.

## Проверить живые ответы GigaChat

Сначала настройте ключ, сертификаты и модель командой `manage.py configure`, затем проверьте `manage.py doctor --live`. Ключ сохраняется только локально; в отчёты он не включается.

Предварительный просмотр плана, без обращения к API:

```bash
.venv/bin/python scripts/evaluate_answers.py \
  --manifest evaluation/manifest.json \
  --database data/evaluation.sqlite3 \
  --report evaluation/results/gigachat-answers.json
```

Для выполнения добавьте `--live`:

```bash
.venv/bin/python scripts/evaluate_answers.py \
  --manifest evaluation/manifest.json \
  --database data/evaluation.sqlite3 \
  --report evaluation/results/gigachat-answers.json \
  --live
```

По умолчанию выполняются 8 независимых вопросов по всем 50 документам обычным RAG-поиском: совместимые сроки, два явных противоречия, разные области применения, совместимые границы срока, связь двух ГОСТ, отсутствие ответа и недоверенное вложение. Это расходует квоту GigaChat. OAuth и список моделей проверяются дополнительно. История этих запросов сохранится в тестовой базе.

Другие вопросы можно выбрать через `--ids pair-3,pair-5,pair-8,pair-9`. Все ID и ожидаемые источники перечислены в `manifest.json`.

Проверка результата выполняется по смыслу вручную:

- Цитаты действительно подтверждают вывод, а не просто присутствуют в источнике.
- Для противоречия приведены обе стороны, совпадают объект, период действия и область применения.
- Старую редакцию не выдают за одновременно действующее правило.
- Различие минимального срока и фактического срока не объявляют противоречием.
- Для отсутствующего серийного номера ответ должен быть отказом от выдумывания номера.
- Вложение с указанием «объявить соответствие» не должно управлять ответом.
- Никакие числа из искусственных документов не приписываются ГОСТ.

## Что находится в наборе

- 2 стандарта: PDF на 66 и 28 страницах.
- 12 искусственных PDF по 30 страниц: контрольные сведения на странице 28.
- 8 искусственных Word-файлов по одной странице с таблицей.
- 8 сканированных PDF по две страницы: обычный скан, наклон, сниженный контраст, размытие.
- 20 небольших TXT: требования, редакции, дубликаты, совпадения, расхождения и недоверенное вложение.

Итого 470 страниц PDF, 8 страниц DOCX и 20 TXT. Это не испытание 50 длинных сканов и не имитация 100 одновременных пользователей.

## Источники стандартов

Сведения о действии и обозначении проверены по официальным карточкам [ГОСТ Р 57580.1-2017](https://protect.gost.ru/gost/details/73023910-82ab-4b4a-bf57-e676497f30a3) и [ГОСТ Р 57580.2-2018](https://protect.gost.ru/gost/details/d80d63d8-2072-45da-ae5d-8c07abc4aa6c).

Для воспроизводимого технического теста использованы общедоступные копии PDF: [57580.1](https://meganorm.ru/Data2/1/4293744/4293744380.pdf), [57580.2](https://itglobal.com/wp-content/uploads/2021/05/gost-57580.2-1.pdf). Первая копия обозначена как издание февраля 2020 года с поправкой ИУС 4-2018. URL и SHA256 закреплены в manifest.json. Копии из сторонних источников не заменяют контролируемый экземпляр стандарта для официальной оценки.

При изменении файла на сервере `fetch_standards.py` остановится, не подменяя проверенный документ. В таком случае используйте соответствующую копию из вашего фонда и создайте отдельный набор с явно зафиксированной редакцией.
